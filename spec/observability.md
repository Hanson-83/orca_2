# 可观测性与错误处理

参考：Twelve-Factor（Logs）、常见结构化日志实践

## 日志

- 使用标准日志库（如 Python `logging`），避免无级别 `print` 充作生产日志。
- 结构化优先（时间、级别、模块、请求 / 任务 ID、关键字段）。
- 级别约定：`DEBUG` 细节、`INFO` 关键业务事件、`WARNING` 可恢复异常、`ERROR` 失败、`CRITICAL` 系统不可用。
- 禁止记录密钥与过量个人隐私；设备原始报文可截断或哈希后归档。

## 错误与重试

- 区分可重试（超时、短暂断连）与不可重试（参数非法、鉴权失败）。
- 重试需上限与退避；对硬件动作避免盲目重试导致重复执行（幂等或状态机保护）。
- 向上游返回明确错误码 / 错误类型，便于 UI 与调度层处理。

## 追踪与指标（按需）

- 长流程（任务 / 工作流）具备可关联的 ID，贯穿日志与状态文档。
- 关键路径可统计延迟、成功率、队列长度；先满足日志与状态可读，再加复杂 APM。
