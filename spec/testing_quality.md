# 测试与质量

参考：[Google Engineering Practices](https://google.github.io/eng-practices/review/reviewer/looking-for.html)（变更应有恰当测试；测试须能在实现错误时失败）

## 原则

- 测试保护行为，不保护实现细节。
- 有逻辑变更的改动，原则上同批补充 / 更新测试（紧急修复可随后补，但需记录）。
- 重构前尽量具备可重复的基线测试。

## 测试分层（按需选用）

| 层级 | 关注点 | 示例 |
|------|--------|------|
| 单元 | 纯逻辑、适配器契约 | 解析、调度算法、协议编解码 |
| 集成 | 模块协作、DB / 中间件 | API + 仓储、网关 + 模拟设备 |
| 端到端 / 冒烟 | 关键用户路径 | 启动 → 下发任务 → 完成回执 |
| 硬件在环（如适用） | 真机 / 半实物 | 单独标记，默认 CI 可跳过 |

## 实践要点

- 断言明确、失败信息可读；避免永远为真的弱断言。
- 外部依赖可替换：设备、网络、时钟等通过接口注入，便于假对象 / 录制回放。
- 测试数据与密钥不进仓库；用 fixture / factory 生成。
- 不稳定测试（闪烁）优先修复或隔离，禁止长期 `@skip` 掩盖问题。

## 完成定义（DoD，默认）

变更可视为完成前，按适用性核对：

1. 相关 lint / 类型检查通过
2. 相关单测 / 关键冒烟通过
3. 配置与接口文档已更新（若有契约变更）
4. 无密钥与大型无关 diff
5. 风险操作已确认并记入操作日志（若适用）
