# 接口与适配层约定

适用于 HTTP API、进程内模块边界、数据库访问与**硬件设备**接入。对齐「网关 / 适配层」架构（见 `tech_stack.md`）。

参考：Twelve-Factor Backing Services；API 设计常见实践（资源导向、显式版本、稳定错误模型）

## 总则

- 业务逻辑只依赖抽象接口，不直接依赖具体驱动、SDK 或 SQL 细节。
- 每个外部系统（DB、PLC、机械臂、相机、远端服务）对应清晰适配器，可替换、可模拟。
- 契约变更（字段、语义、单位、坐标系）须同步文档与测试，并评估调用方。

## HTTP / 应用 API（如适用）

- 前后端分离时以 OpenAPI / 等价 schema 或简明日志描述契约。
- 显式版本或兼容策略；破坏性变更走新版本或特性开关。
- 统一错误结构（码、消息、可重试标记）；时间与单位在文档中写明。

## 设备与工业协议

- 适配层封装连接、心跳、超时、重连与报文编解码；上层只发领域命令（如 `move_absolute`、`grasp`）。
- 协议细节（Modbus 寄存器、厂商私有帧等）留在适配层，不泄漏到业务编排。
- 明确：坐标系、单位、安全限位、急停与幂等语义。
- 提供 Fake / Simulator 实现，供无硬件环境开发与 CI。

## 配置驱动

- 设备型号、地址、波特率、话题名等放配置（YAML），代码读配置装配适配器。
- 新增设备类型优先加适配器 + 配置，而非改业务主流程。

## 数据库

- 访问经仓储 / DAO 适配；连接串与凭证外置。
- 迁移有版本记录；禁止生产环境手工改表而不留痕迹。
